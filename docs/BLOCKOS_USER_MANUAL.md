## 第一章：系统核心理念与架构总览

### 1.1 核心痛点与范式颠覆
传统协同工具（Word、标准 Wiki、线性文档）本质上是“单向垂直排列的静态文本容器”：
- **信息锁死**：长达数十页的长篇文档，需求、技术实现、UI 规范与测试用例混杂在一起，检索与跨职能协同成本极高；
- **AI 边缘化**：市面多数产品仅是在右侧边缘嵌入一个单薄的聊天气泡（Chatbox），AI 无法真正理解文档的网状依赖关系，更无法直接操控内容；
- **工具割裂**：PRD 文档（Notion）、开发任务（Jira/Linear）、时序进度（甘特图）彼此孤立，跨系统同步极易滞后甚至脱节。

### 1.2 BlockOS 的解法：`(agent + md) × ai + html`
BlockOS 彻底打碎“单体长篇文件”概念，以 **原子级 Block（块）** 作为基本知识单元：
- **`md` (Markdown 语义内核)**：所有文本与逻辑 Block 采用清晰标准格式，保留高迁移性与易读性；
- **`agent` (自主行动规则)**：赋予 Block 事件响应机制，支持勾选任务自动触发状态机流转与审计留痕；
- **`ai` (环境乘数因子)**：AI 原生嵌入卡片微操作、全局指令条与双向图谱，成为真正的副驾操作者；
- **`+html` (开放渲染层)**：基于 Web 标准（React 19 + Tailwind CSS + @dnd-kit），赋予每个 Block 自由拖拽、三向伸缩、树状挂载与全尺寸自由排版能力。

### 2.1 画布基础漫游与导航
1. **滚轮平移**：在画布任意空白区域滑动鼠标滚轮，实现画幅上下平滑滚动；
2. **缩放画幅**：按住 <kbd>Ctrl</kbd> 键（Mac 上为 <kbd>Cmd</kbd>）并滑动滚轮，或点击右下角 `+` / `−` 控制器，在 `50% ~ 200%` 舒适区间缩放；
3. **鹰眼小地图 (Canvas Minimap)**：
   - 位于右下角的悬浮面板，等比例微缩投影当前画布上的所有 Block 节点；
   - 内部带有半透明蓝色高亮框，代表当前屏幕视口覆盖范围；
   - **交互漫游**：可直接在小地图中点击任意位置快速将视口居中，或按住半透明框拖拽实现全景快速巡航；支持一键十字准星复位全览。

### 2.2 Block 卡片自由排版与微交互
1. **自由移动**：按住任意 Block **顶部标题栏或把手**即可自由拖拽至画布任意二维坐标；
2. **三向自由伸缩拉伸**：
   - **右边缘把手 (`↔`)**：横向调节卡片宽度（单列标准 760px，支持自由拓宽）；
   - **底边缘把手 (`↕`)**：纵向调节卡片高度，完整呈现长篇代码或多行表格；
   - **右下角对角把手 (`⤡`)**：宽高双向自由延展；
3. **智能垂直推移避让 (Smart Push-down)**：
   - 当纵向拉长某张卡片时，系统内置物理包围盒碰撞算法，会自动将该卡片下方同列的 Block 整体平滑推移避让 60px，彻底消解重叠覆盖；
4. **深浅色主题自适应**：
   - 点击右上角太阳/月亮图标，全站 UI、卡片线框、表格与代码块瞬时切换 Dark / Light 主题，文字排印通过 WCAG AA 高对比度认证。

## 第四章：子 Block 树状嵌套与思维导图双向互通

为打破白板卡片杂乱无章的通病，BlockOS 提供了严谨的**父子嵌套（Sub-Block Hierarchy）引擎**：

```
┌────────────────────────────────────────────────────────┐
│ 需求核心卡片 (Parent Block: "用户鉴权体系重构")          │
│   ├── [子 Block 1] 待办: "实现 Bearer Token 验证"       │
│   ├── [子 Block 2] 代码: "api-keys.ts 核心签名算法"      │
│   └── [子 Block 3] 表格: "权限矩阵表 (Read/Write/Admin)"│
└────────────────────────────────────────────────────────┘
```

1. **父子挂载方式**：
   - **手动编排**：拖动任意 Block 至目标 Block 右侧侧翼，在卡片菜单中选择「作为子卡片挂载」；
   - **内置 AI 自动编排**：直接输入口语化指令（如“将卡片B设为卡片A的子Block”）；
   - **外部 MCP 编排**：外部 Agent 调用 `set_subblock` 或 `batch_create_hierarchy` 自动批量组装；
2. **层级视觉特征**：
   - 子 Block 自动获得视觉缩进与父子树状指引线；
   - 支持在父卡片上一键**折叠/展开**全部子卡片，轻松收纳数十个派生模块；
   - 移出子 Block 时，卡片自动提升回根层级独立卡片，绝不会导致内容丢失；
3. **架构导图与落地 Block 双向互通**：
   - 点击思维导图或架构图的特定节点，画布自动平滑聚焦至该节点对应的落地实现 Block；反向在 Block 中点击关联标签，亦可点亮导图中的全局拓扑位置。

## 第五章：内置 AI 智能体套件与工具调用

BlockOS 内置了阿里云百炼 / 阿里通义大模型内核，AI 不再是边缘对话气泡，而是渗透于交互全流程：

### 5.1 全局 AI 指令条与工具调用 (Tool-Calling)
- **唤起方式**：点击顶栏【AI 助手】按钮，或按下全局快捷键 <kbd>Ctrl+K</kbd> / <kbd>Cmd+K</kbd>；
- **支持的高阶工具调用指令**：
  - **批量层级创建**：`"创建1个需求Block，并创建2个子Block"`（AI 会自动生成 1 个核心卡片，并自动在侧翼挂载生成 2 个子任务卡片）；
  - **动态设为子卡片**：`"将模块B设为模块A的子Block"`；
  - **解耦提升**：`"移出模块B的子Block"`；
  - **拓扑建网**：`"将卡片A与卡片B建立关联"`；
  - **批量操作**：`"高亮所有包含安全合规的Block"`、`"删除包含测试字样的临时Block"`。

### 5.2 单 Block 专属 ✨ (Sparkles) 快捷 AI
悬停在任意卡片右上角点击 ✨ 图标，即可触发类型自适应的智能操作：
- **文本块**：一键生成总结、扩写扩充、润色为专业 PRD 规范、一键转为交互式思维导图；
- **代码块**：代码逻辑解释、性能与安全漏洞分析、生成单元测试用例；
- **数据表格**：数据趋势洞察、计算异常值、生成结构化结论。

### 5.3 幽灵补全 (AI Ghost Text Autocomplete)
- 在文本 Block 中键入文字后稍作停顿（1.5 秒），AI 会在光标后呈现半透明的灰色建议文字；
- 按下 <kbd>Tab</kbd> 键瞬间采纳建议，继续敲击键盘则自动忽略无感打扰。

### 5.4 角色透视折叠引擎 (Role-Perspective Folding)
- **核心哲学**：**单一事实源 (Single Source of Truth)，原文零篡改**；
- 在顶栏切换角色视角（如从“产品经理”切换至“测试工程师”）：
  - 系统不会生成新副本，而是通过透视算子自动将非该角色核心关注的 Block 折叠为轻量微锚点（Folded Anchor）；
  - 极大压缩视觉噪音，让各工种在同一份文档中只聚焦于自己的关切点。

## 第七章：Agent 自动化规则自驱动与审计溯源

BlockOS 支持在文档中编排由事件驱动的自动化 Agent 规则（位于“规则引擎”面板）：

### 7.1 开箱即用的企业级敏捷交付流转规则
在新手入门画布中，预置了【需求验收与交付自动化】规则：
- **触发条件**：待办卡片被勾选验收（`block.type === 'todo' && block.meta.checked`）；
- **自动执行链路**：
  1. **Action 1 (日志归档)**：自动在下方生成【📋 迭代发布报告】卡片，注入时间戳、质量验收合格证明与协同状态流转证明；
  2. **Action 2 (AI 衍生决策)**：自动调用大模型，流式规划并生成【🚀 下一步上线保障与测试 Checklist】卡片（涵盖灰度放量、核心指标监控与应急预案）。
- **防重与幂等保证**：取消勾选重新勾选时，系统会自动就地刷新卡片指纹，绝不发生重复堆叠。

### 7.2 审计留痕与版本可逆回滚 (Audit Log)
- 任何由 Agent 或 AI 辅助产生的变更均被打上不可篡改的审计指纹（Timestamp、操作者/Agent ID、Delta Diff 变更前后对比）；
- 团队可在「Agent 日志」面板随时查看每一条流水，并支持一键**原子回滚**，确保团队操作高安全、可溯源。

## 第八章：外部 Agent 开放生态 (MCP & Open API)

BlockOS 现已原生打通 Model Context Protocol (MCP) 标准，使外部独立智能体可以把 BlockOS 作为自己的外部画布知识库直接调用。

### 8.1 接入配置方式速查

#### 场景 A：Cursor / Claude Desktop 客户端 (stdio 标准协议)
在您的 `claude_desktop_config.json` 或 `.cursor/mcp.json` 中添加配置：

```json
{
  "mcpServers": {
    "blockos": {
      "command": "node",
      "args": [
        "/path/to/BLOCKOS/scripts/blockos-mcp-stdio.js"
      ],
      "env": {
        "BLOCKOS_URL": "https://blockos.hiakkocv.xyz/api/open/v1/mcp",
        "BLOCKOS_API_KEY": "your_blockos_api_key_here"
      }
    }
  }
}
```
*(注：请将 `/path/to/BLOCKOS` 替换为您本地克隆该项目的实际根目录路径)*

#### 场景 B：自研 Python 脚本 / LangChain / AutoGPT (HTTP JSON-RPC)
无需任何第三方私有库，直接通过标准 HTTP POST 请求调用：

```python
import requests

BLOCKOS_MCP_URL = "https://blockos.hiakkocv.xyz/api/open/v1/mcp"
HEADERS = {
    "Authorization": "Bearer your_blockos_api_key_here",
    "Content-Type": "application/json"
}

# 调用 MCP tools/list 获取工具，或调用 tools/call 操控画布
res = requests.post(BLOCKOS_MCP_URL, headers=HEADERS, json={
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {
        "name": "create_block",
        "arguments": {
            "type": "text",
            "title": "外部 Agent 派发需求",
            "content": "这是一份由外部 Claude Agent 直接写入 BlockOS 画布的说明卡片。"
        }
    }
})
print("创建结果:", res.json())
```

### 8.2 现有 6 大 MCP 工具能力矩阵与边界

| 工具名称 | 功能描述 | 边界与约束 |
| :--- | :--- | :--- |
| `read_canvas` | 读取画布所有卡片与层级树 (`blockTree`) | 支持指定 `pageId`，缺省自动读取最新画布 |
| `create_block` | 在画布创建单张卡片 | 可选传入 `parentId` 自动作为子卡片挂载 |
| `batch_create_hierarchy` | 一步创建 1 个父 Block 并挂载 N 个子 Block | 自动计算侧翼无重叠排布坐标 |
| `set_subblock` | 将现有卡片设为子卡片，或移出提升为独立卡片 | 传入 `parentId: null` 即可解除嵌套 |
| `create_link` | 在两张卡片之间建立拓扑连接关系 | 小地图与关系图谱中即时呈现连线 |
| `delete_block` | 删除卡片并安全解耦名下子卡片 | 子卡片自动提升回根层级，杜绝悬空孤儿数据 |

> [!NOTE]
> **边界说明**：当前 MCP 聚焦于白板画布层面的完全操作。系统后台的敏捷看板任务流转、PDF 导出、团队架构管理目前通过系统 REST API 开放，后续根据需求可热插拔扩展为更多 MCP Tools。

## 第九章：双端职责分离与移动端章节大纲阅读

为保障在各种设备下的最佳体验，BlockOS 坚持**“双端职责分离，各司其职”**：

- **桌面端 (Desktop Workspace)**：定位为**创作与编排工坊**。基于无限二维漫游白板，提供全量拖拽把手、三向伸缩、关系图谱、敏捷看板与代码沙箱；
- **移动端 (Mobile Workspace)**：定位为**沉浸式消费与章节大纲阅读器**。
  - **章节大纲引擎 (`document-outline.ts`)**：自动将散落的 Block 识别并重组为自上而下的优雅流动长文；
  - **阅读保护机制**：移动端默认以只读与轻量修改为主，任何移动端的文字更新**绝不改变桌面端的 2D 坐标排版**，彻底杜绝手机误触导致桌面白板布局崩塌。

## 第十章：企业级数据安全与离线高可用治理

### 10.1 全链路 AI 原生安全防御体系 (OWASP for LLM)
1. **Pre-flight 入参前置安全漏斗 (0 成本本地毫秒级过滤)**：
   - **提示词注入与越狱拦截 (LLM01)**：自动阻断 `Ignore all previous instructions`、DAN/开发者模式、系统提示词窥探等恶意指令，直接返回 HTTP 400；
   - **敏感机密探针阻断 (LLM06)**：严密阻断试图窃取 `API_KEY`、`POSTGRES_URL` 等环境变量的恶意探测；
   - **DoS / ReDoS 边界熔断 (LLM04)**：严格限定单条提示词 16KB、总上下文 64KB，在 <5ms 内完成静态校验，杜绝账单 DoS 攻击。
2. **Post-flight 出参后置净化漏斗**：
   - **敏感凭据自动脱敏清洗 (`scrubSecrets`)**：扫描模型生成内容中的 `sk-*`、连接串、Token，自动打上 `[REDACTED_*]` 掩码；
   - **存储型 XSS 彻底剥离 (`sanitizeAiOutput`)**：彻底剥离 `<script>`、`<iframe>`、`javascript:` 伪协议与任何畸形 `onerror`/`onload` 注入；
   - **越权分配保护 (LLM07)**：AI 推荐的任务分配人必须存在于项目当前成员白名单中，防范越权提权。

### 10.2 数据存储与离线自愈架构
1. **WebAssembly SQLite (sql.js) 内存内核**：本地保持零网络延迟的 60fps 极速读写，保证全套 SQL 关系查询兼容性；
2. **Neon (Vercel Postgres) 远端快照同步**：每次修改异步将二进制 Base64 快照回传云端持久化；
3. **离线降级与断网自愈队列**：网络偶发波动或断网时，修改自动写入前端 `localStorage('block-os-offline-pending')`；一旦检测到网络恢复（window `online` 事件），无感自动补偿同步上云，数据绝不丢失。

### 常见问题与排障备忘 (FAQ)

**Q1：如何为外部 Agent 申请一个独立的 API Key？**
> 登录 BlockOS 平台后向 `POST /api/open/keys` 发送请求（或通过系统设置中心一键生成），即可生成带有 `bk_live_` 前缀的 64 位安全随机密钥。请妥善保存您的私有 Key，切勿公开或提交至公共仓库。

**Q2：如果我把父 Block 删除了，里面的子 Block 会丢吗？**
> 绝对不会。BlockOS 实现了**级联安全解耦机制**。当父 Block 被删除时，其挂载的所有子 Block 会被自动安全提升为画布的独立卡片，绝不会发生数据隐式丢失或孤儿悬空。

**Q3：移动端修改了文字，会打乱我电脑上精心排好的卡片位置吗？**
> 不会。移动端与桌面端实现了**职责分离架构**。移动端仅负责同步更新卡片的文本、待办与元数据，卡片在桌面画布上的 `x, y, width, height` 物理坐标被严格只读锁定，手机上无论如何翻阅编辑，电脑端布局 100% 保持原样。
