## 模块一：用户洞察与问题定义

### 1.1 目标用户

BlockOS 面向以下三类核心用户群体：

- **初创团队技术负责人**：需要快速将产品构想转化为可执行的项目计划，同时协调设计师、前后端工程师、测试人员等多角色协作。
- **中小型项目管理者**：负责 5-20 人规模的项目，需要直观的任务看板、时间线管理和团队资源分配视图。
- **独立开发者 & 自由职业者**：需要一款轻量但功能完整的个人项目管理工具，支持从需求文档编写到任务追踪的全流程。

### 1.2 用户痛点

通过对目标用户的深度访谈和场景观察，我们识别出以下核心痛点：

| 痛点编号 | 痛点描述 | 影响程度 |
|---------|---------|---------|
| P1 | **计划书 → 任务断层**：产品经理写完 PRD 后，需要手动拆解成任务并分配给成员，过程耗时且容易遗漏 | 🔴 高 |
| P2 | **工具碎片化**：文档、看板、甘特图、团队管理分散在不同工具，信息同步成本高 | 🔴 高 |
| P3 | **进度可视化不足**：传统看板只能看状态，无法直观看到时间维度的进度和依赖关系 | 🟡 中 |
| P4 | **权限管理粗糙**：现有工具要么全员可见，要么配置复杂，不适合小团队快速上手 | 🟡 中 |
| P5 | **AI 能力浮于表面**：很多工具号称 AI，但仅提供文案润色，无法真正介入工作流 | 🟡 中 |

### 1.3 使用场景

**场景 A：AI 导入项目计划**  
产品经理 akko 完成了一份电商平台 PRD 文档，将其粘贴到 BlockOS 的 AI 分析面板。系统自动识别出「需求分析 → UI 设计 → 前后端开发 → 测试上线」四个阶段，生成 12 个具体任务，自动分配到团队 4 名成员，并生成甘特图。整个过程从原来的 2 小时缩短到 3 分钟。

**场景 B：团队资源管理**  
团队负责人需要查看「前端组」成员当前负载。在团队管理面板中，一眼看到 akko（前端）有 3 个进行中任务、1 个待办，而另一位成员已超负荷。随即通过拖拽调整任务分配。

**场景 C：个人工作中心**  
开发者登录后进入个人中心，看到自己在三个项目中的任务分布、本周截止的里程碑、以及待处理的高优先级任务。无需在各个项目间切换，一站式管理个人工作。

## 模块二：产品方案设计

### 2.1 产品概述

BlockOS 是一款 **AI 原生的模块化协作操作系统**，核心理念是「Block（积木）」—— 将文档、任务、看板、甘特图、团队管理等能力封装为可自由组合的模块。用户像搭积木一样构建自己的工作空间，而 AI 则作为「智能助手」贯穿整个工作流，实现从需求输入到任务执行的无缝衔接。

**产品定位**：Notion × Jira × Linear 的 AI 增强融合体，专为中国中小团队优化。

### 2.2 核心功能

#### 功能矩阵

| 功能模块 | 核心能力 | AI 增强 |
|---------|---------|---------|
| **智能文档** | Block 级富文本编辑（文本、图片、视频、公式、代码块、嵌入链接） | AI 续写、智能排版建议 |
| **AI 项目导入** | 粘贴 PRD / 计划书 → 自动切分任务 | 基于 LLM 的结构化解析 + 任务分配 |
| **多维看板** | 待办 / 进行中 / 已完成三栏拖拽 | 智能优先级推荐 |
| **甘特图** | 时间线视图，显示起止日期、周数、进度 | 自动计算关键路径 |
| **里程碑管理** | 项目关键节点追踪 | AI 建议里程碑设置 |
| **团队管理** | 成员增删、角色分配、项目关联 | — |
| **个人中心** | 跨项目任务聚合、个人信息管理 | 工作负载分析 |
| **权限控制** | 管理者 / 员工双角色，数据级隔离 | — |

#### 功能亮点详解

**1. Block 级文档系统**  
文档不是一整段文本，而是由独立 Block 组成。每个 Block 支持：
- 富文本、图片（支持本地上传 base64 预览）、视频/音频（直接播放）、公式（LaTeX 实时渲染）、嵌入链接（YouTube/Bilibili iframe 嵌入）
- Block 间自由拖拽排序
- Block 间创建依赖链接，形成知识图谱

**2. AI 项目导入**  
用户粘贴任意 Markdown 格式的项目计划书，AI 自动：
- 提取项目阶段和任务列表
- 识别任务优先级和依赖关系
- 根据团队成员职能自动分配任务
- 生成甘特图时间线
- 输出项目优缺点分析报告

**3. 甘特图引擎**  
自研 SVG 甘特图，支持：
- 精确到天的起止时间显示
- 自动计算并显示第几周
- 任务状态颜色编码（待办/进行中/已完成）
- 响应式布局，自适应容器宽度

## 模块三：AI 原生能力说明

### 3.1 AI 核心能力

BlockOS 的 AI 能力不是「锦上添花」，而是**产品核心工作流的基础设施**。我们基于 SiliconFlow 提供的 Qwen3-8B 大模型，构建了三个核心 AI 能力：

#### 能力一：项目计划智能解析（AI Import）

**输入**：任意 Markdown 格式的项目计划书 / PRD / 执行方案  
**输出**：结构化任务列表（含标题、描述、优先级、建议执行人、时间线）

**技术实现**：
- 使用 `streamText` 流式输出，降低用户等待感知
- Prompt 工程精确约束输出格式为 JSON Schema
- 后端自动将 AI 输出映射为数据库实体（Task、Milestone）
- 根据团队成员职能标签智能匹配 assignee

**示例 Prompt 结构**：
```
System: 你是一位资深项目经理，擅长将项目计划书拆解为可执行的任务清单。
要求：
1. 识别项目阶段（phase）
2. 每个阶段拆解为具体任务（task）
3. 为每个任务标注：优先级、建议执行角色、预估工期
4. 输出严格 JSON 格式
```

#### 能力二：智能续写（AI Generate）

**场景**：用户在文档中写下「我们需要一个用户登录系统…」，AI 自动续写完整的技术方案。  
**技术实现**：流式文本生成，支持实时预览，用户可随时接受或放弃。

#### 能力三：项目分析（AI Analyze）

**输入**：项目计划书  
**输出**：项目优缺点分析、风险提示、资源建议  
**价值**：帮助团队在启动前识别潜在问题，优化执行策略。

### 3.2 AI 如何解决用户痛点

| 用户痛点 | AI 解决方案 | 效果 |
|---------|-----------|------|
| 计划书 → 任务断层 | AI Import 自动解析并生成任务 | 从 2 小时 → 3 分钟 |
| 任务分配不合理 | AI 根据成员职能自动匹配 assignee | 减少人为遗漏和偏见 |
| 进度规划困难 | AI 自动计算时间线和里程碑 | 可视化项目全貌 |
| 文档撰写效率低 | AI 续写辅助技术方案 | 提升 3 倍写作效率 |
| 项目风险评估不足 | AI Analyze 输出优缺点报告 | 提前识别 80% 常见风险 |

### 3.3 AI 技术方案

```
┌──────────────────────────────────────────────┐
│              前端交互层                        │
│  - AI 分析面板（Markdown 粘贴区）              │
│  - 流式结果预览（Skeleton + 渐进渲染）          │
│  - 一键确认导入（事务性批量写入）               │
├──────────────────────────────────────────────┤
│              API 路由层                        │
│  /api/projects/[id]/ai-import    POST        │
│  /api/projects/[id]/ai-analyze   POST        │
│  /api/ai/generate                POST        │
├──────────────────────────────────────────────┤
│              AI SDK 层                         │
│  ai@6.0.177 + SiliconFlow Provider           │
│  - streamText: 流式生成                       │
│  - maxOutputTokens: 2048                      │
│  - temperature: 0.7（平衡创造性和准确性）        │
├──────────────────────────────────────────────┤
│              大模型层                          │
│  Qwen3-8B (SiliconFlow API)                  │
│  - 支持中文技术文档理解                        │
│  - 支持结构化 JSON 输出                        │
└──────────────────────────────────────────────┘
```

**关键技术决策**：
- 选择流式输出而非一次性返回：降低用户等待焦虑，提升 perceived performance
- 选择 Qwen3-8B：中文理解能力强，性价比高，适合 Demo 场景
- 结构化 JSON 输出 + 后端校验：确保 AI 输出可靠，避免前端解析失败

## 模块四：加分项

### 4.1 落地可行性

**技术栈成熟度**：
- Next.js 15 + React 19：业界主流，生态完善
- sql.js (SQLite WASM)：无需部署数据库服务器，降低运维成本
- Tailwind CSS + shadcn/ui：快速构建美观 UI
- Zustand + Immer：轻量状态管理，学习成本低

**部署方案**：
- **Vercel 一键部署**：适合海外用户，自动 CI/CD
- **腾讯云轻量服务器**：适合国内用户，提供完整部署脚本（`setup.sh`）
- **本地运行**：`start.bat` 一键启动，适合私有化部署

**成本控制**：
- 前端静态托管：免费（Vercel Hobby）或 ￥50/月（腾讯云）
- AI API：按量付费，Demo 场景月均 ￥20-50
- 无后端服务器成本：sql.js 纯前端运行

### 4.2 商业化思考

**商业模式画布**：

| 维度 | 策略 |
|-----|------|
| **目标市场** | 中国 500 万+ 中小研发团队、自由职业者 |
| **价值主张** | AI 驱动的「文档 → 执行」一站式协作 |
| **收入来源** | SaaS 订阅（免费版 + Pro 版 ￥29/人/月） |
| **渠道** | 开发者社区、Product Hunt、技术博客 |
| **成本结构** | AI API + 服务器 + 开发人力 |

**差异化竞争策略**：
- **vs Notion**：更强的任务管理和 AI 导入能力
- **vs Jira**：更轻量、更易上手、文档能力更强
- **vs Linear**：更好的中文支持和本地化部署
- **vs 钉钉/飞书**：更聚焦研发场景，不臃肿

**未来演进路线**：
1. **V1.0（当前）**：核心协作功能 + AI 导入
2. **V1.5**：接入 Git 代码仓库，关联提交与任务
3. **V2.0**：AI 自动周报生成、智能提醒、预测延期风险
4. **V2.5**：开放插件市场，支持第三方 Block 扩展

### 4.3 其他亮点

- **极致的 Demo 体验**：预制管理者/员工账号、预制团队/项目/任务数据，评委打开即可体验完整工作流
- **完整的权限模型**：管理者看全部，员工只看自己，真实模拟企业场景
- **响应式设计**：支持桌面端和平板端，随时随地管理项目
- **零配置启动**：`npm install && npm run dev` 即可运行，降低体验门槛
